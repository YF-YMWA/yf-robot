# 内容模型：三种库各管什么

她脑子里现在有三种「资料」，加上素材库一共四种。这份文档说清谁管什么，
以及为什么**不能合并**。

---

## 一句话区分

| 库 | 存的 | 例子 |
|---|---|---|
| **知识库** | 某件事**是什么** | 「我不吃香菜」「下午两点到四点午睡」 |
| **逻辑库** | 遇到情况**怎么做** | 「被骂先别软」「问价先问预算」 |
| **词库** | 说话**像什么** | 「破防了」「蚌埠住了」「yyds」 |
| **素材库** | 有哪些**图**能发 | 39 张表情包，按情绪分类 |

---

## 为什么不能合并

它们的**检索方式完全不同**：

| | 知识库 | 逻辑库 | 词库 |
|---|---|---|---|
| 触发方式 | 按这句话**检索** | 按这句话**检索** | 按**语气**整类注入 |
| 相关性 | 必须相关才注入 | 必须相关才注入 | 不判相关，只看语气 |
| 信息形态 | 长段落（300~500 字） | 一句话（60 字内） | 词表（几百字） |
| 更新方式 | 导入文档 | 手写 / 网页学 | 手写 / 自动学 |
| 失效场景 | 文档过时 | 情况变了 | 网络梗过气 |

**把词库并进知识库会怎样**：每次提问都去检索「破防了」这个词和问题相不相关 ——
多半不相关，于是一个词都注入不进来，她说话立刻变得很干。
反过来把知识库并进词库也不行：词库是随机抽的，抽到「下午两点午睡」
这种和当前话题无关的段落，纯属干扰。

---

## 统一的是「注入」，不是「存储」

存储分开（各自的数据文件和编辑界面），但**拼进提示词这一步统一了**。

`core/context.mjs` 负责：

```
1. 收集：知识库命中 + 逻辑库命中 + 素材摘要 + 词库（按语气选类）
2. 排队：经验 → 资料 → 素材 → 风格
3. 去重：事实和经验措辞重合时只留经验（更可执行）
4. 封顶：总预算 1600 字，各类按比例分
```

预算分配：

| 内容 | 占比 | 典型字数 |
|---|---|---|
| 经验（逻辑库） | 30% | ~480 |
| 资料（知识库） | 28% | ~450 |
| 素材提示 | 10% | ~120 |
| 风格（词库） | 32% | ~512 |

### 为什么词库要按语气挑

词库全拼约 1900 字（≈1150 token），而且是**每轮都发**——
比偶尔命中的知识库还贵。

但实际上多数时候只用得上一类：

| 语气 | 拼哪几类 | 字数 |
|---|---|---|
| 被骂（hostile） | 只要回怼库 | ~690 |
| 闲聊（casual） | 网络用语 + 缩写 | ~1260 |
| 正经（serious） | 只要缩写 | ~514 |

实测每轮省下约 **1000 token**（输入从 4500 降到 3500）。

## 素材库的特殊之处

素材库不是「文本资料」，是**能力提示**。

它只在两种情况下出现：

1. 这句话里提到「表情 / 图 / 发图 / 来张图」
2. 命中的经验或资料里提到图

出现时只说三件事：**有几张、什么情绪、怎么挑**。
具体挑哪张还是走 `list_stickers` / `send_image` 工具。

这样「什么时候该发」（经验决定）、「有哪些可选」（素材摘要）、
「怎么发」（工具）三件事就串起来了。

## 联网学习有两条路，抓取是同一套

| 路径 | 学什么 | 存到哪 |
|---|---|---|
| 联网学习词（`learning.mjs`） | 网络用语、表情包 | 词库 / 素材库 |
| 联网学逻辑（`logic-learn.mjs`） | 处理经验 | 逻辑库 |

两者**抓取都走 `core/safe-fetch.mjs`**：

- 只允许公网 http/https
- 拒绝 file 协议、内网地址、云元数据、非常规端口
- 限制响应大小
- 跳转逐跳校验

> 以前 `learning.mjs` 是自己写 fetch 的，只检查了协议 —— 抓
> `http://127.0.0.1:8899/api/admin/config` 也能拿到东西。现在统一了。

## 以后新增「库」时的判断标准

先问三个问题：

1. **靠什么触发？** 按内容检索 → 归到「检索类」；按场合整类上 → 归到「风格类」
2. **多长？** 一句话 → 逻辑库；一段话 → 知识库；一批词 → 词库
3. **会不会过时？** 会 → 需要审核和淘汰机制

答不上来就别急着建新库 —— 先看看能不能塞进现有三种里。
每多一个库，就多一份注入预算的争夺，也多一处要维护的界面。
