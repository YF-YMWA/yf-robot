# 借鉴大模型原理的优化点

这套框架不是语言模型，但很多「模型为什么会这样」的原理，可以直接搬到工程实现上。
下面每一条都是**已经落在代码里**的，不是设想。

---

## 1. 上下文窗口 → 分层预算

**原理**：模型的上下文窗口有限，塞进去的东西要抢位置；不重要的内容挤掉重要内容就是灾难。

**我们**：`core/context.mjs` 给每一类内容分配预算（经验 / 资料 / 素材 / 风格 / 记忆），
超了就按类丢弃，并统计「丢了什么、丢了多少」：

```
[ctx] 经验 1 / 资料 0 / 素材 0 / 风格 1｜共 598 字（丢弃 经验0 资料0）
```

---

## 2. KV 缓存 / prompt caching → 系统提示词前缀稳定

**原理**：推理时前缀不变的部分可以复用缓存，成本和延迟都降下来。
反过来，只要前缀里有一个字变了，缓存全部失效。

**问题**：我们以前把「当前时间」「此刻状态」「心情」「词库」「素材清单」
全拼在系统提示词里。时间是每分钟变的 —— **前缀永远不一样，缓存永远不命中**。

**现在**：system 只留稳定部分（人设、规矩、身份），易变内容挪到本轮提问前面：

```
system   = 人设 + 不要做 + 记忆规矩 + 主人身份   ← 一轮对话里不变
user     = 【本轮情况】现在 14:32 / 心情平静 / 词库… + 对方说的话
```

验证（`tools/check-prefix-cache.mjs`）：

```
早 9 点和晚 21 点的系统提示词一致: 是 ✅（前缀可缓存）
长度: 1006 字
含【当前时间】: 没有 ✅
```

---

## 3. 注意力 / 检索增强 → 按需注入

**原理**：注意力不是把所有信息等权看待，而是「和当前 query 相关的那部分权重高」。

**我们**：不是把知识库、经验库整本塞进去，而是先检索：

- 知识库：向量检索，只取相关片段
- 经验库（logic）：按当前话题搜「以前遇到类似情况怎么处理」
- 素材库：只在聊到图的时候才出现清单

---

## 4. 指令层级 → 身份与权限分层

**原理**：模型对「系统指令 > 用户指令」有天然分层，用来防注入。

**我们**：同样分层：

```
系统提示（人设、禁止事项）
  > 主人身份校验（wxid 比对 / 昵称软识别）
  > 工具权限（非主人直接禁用）
  > 对方说的话
```

昵称对上但没验证 wxid 时，会单独降一档：不叫「主人」、不透露私事、不给工具。

---

## 5. 工具调用（function calling）→ 原生 + 文字协议双通道

**原理**：模型输出结构化调用，外部执行后把结果喂回去。

**我们**：

- 支持 function calling 的服务商 → 原生 `tools` 字段
- 不支持的 → **文字协议**：模型写 `{{tool:send_image {"name":"x.gif"}}}`，
  我们解析、执行、回填结果（最多 3 轮）

后者是为了「换个 Key 不至于功能全废」。

---

## 6. 采样温度 → 说话不重复

**原理**：temperature / top-p 控制输出的随机性；永远取最高概率会复读。

**我们**：`temperature` 可调；另外用词库 + 偶尔的措辞变体（`humanize.mjs`）
避免每句都一个腔调。

---

## 7. 记忆压缩 → 旧对话摘要

**原理**：长上下文不可行，就要压缩。

**我们**：`session.compressAfter` 达到阈值后，把旧对话压成摘要进记忆，
原始轮次丢掉。摘要也会进上下文（在预算内）。

---

## 8. RLHF 的极简版 → 逻辑库（从反馈里学）

**原理**：人类反馈告诉模型「这样回答更好」，下次调整。

**我们**：`logic.json` 记「遇到某类情况该怎么做」。
可以从对话里提取（`learn_from_web`、`autoLearn`），也可以手写。
检索时按话题取用，和模型的自适应不同 —— 这是**显式的、可编辑的**经验。
好处是你能直接改，坏处是不会自动泛化。

---

## 9. MoE 路由（未做，值得做）

**原理**：不同 token 交给不同专家，简单的事不惊动大模型。

**可以怎么用**：按场景选模型 ——
闲聊用小模型、写长文/画图用大模型、看图用视觉模型。
现在我们是「一把 Key 走天下」，多模型只在 fallback 里用。

---

## 10. 自洽性 / 多次采样（未做，值得做）

**原理**：同一问题采样多次，投票取多数，准确率更高。

**可以怎么用**：对含糊指令（「发个那个」）先生成 2 个候选理解，
用规则或廉价模型挑一个，再执行 —— 比一次就赌更稳。
代价是翻倍调用，只适合关键判断（比如要不要发图给谁）。

---

| KV 缓存 | 系统提示词前缀稳定 | ✅ |
| 注意力/检索 | 知识库/经验库按需注入 | ✅ |
| 指令层级 | 人设 > 身份 > 工具 > 用户 | ✅ |
| 工具调用 | 原生 + 文字协议 | ✅ |
| 采样温度 | temperature + 措辞变体 | ✅ |
| 记忆压缩 | 旧对话摘要 | ✅ |
| RLHF | 显式逻辑库 | ✅（弱） |
| MoE 路由 | 按场景选模型 | ❌ 待做 |
