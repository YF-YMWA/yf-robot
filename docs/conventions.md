# 开发约定

用户定下的规矩，写在这里免得忘。

---

## 1. 每项功能都必须有面板入口

**规矩**：新做一个功能，不能只有接口或只靠手敲命令 —— 必须在控制台里有对应的界面。

对照清单（加功能时逐条过）：

- [ ] 有开关或表单（能改、能存）
- [ ] 有列表或状态显示（能看见当前是什么样）
- [ ] 有删除/撤销入口（能反悔）
- [ ] 打开页面时自动加载数据（不用手动点刷新）
- [ ] 校验失败时给一句人话（不是 `undefined` 或英文报错）

**为什么**：这套东西是给人双击就用的，不是给开发者敲 curl 的。
「有接口没界面」等于没有这个功能。

**已有功能的检查结果**：

| 功能 | 面板入口 |
| --- | --- |
| 对话模型 / 看图 / 画图 / 语音 / 搜索 | ✅ 模型与功能页 |
| 工具权限档位 | ✅ 模型与功能页下拉 |
| 审批（微信里问） | ✅ 走对话，无需页面 |
| 记忆（含备份/恢复） | ✅ 记忆页 + 两个 bat |
| 素材库 / 她画的图 | ✅ 素材页 |
| 主动搭话 / 主动画图 | ✅ 主动功能页 |
| **定时任务** | ✅ 主动功能页新增卡片 |
| 联网学习 / 插件 / 逻辑库 | ✅ 各自页面 |
| 后台作业 | ⚠️ 无页面（只影响内部调度，先不加） |

---

## 2. 改完必须自己跑一遍

- `runtime\node.exe tools\run-tests.mjs`（全量单测）
- `runtime\node.exe tools\check-all.mjs`（运行时自检）
- `runtime\node.exe tools\check-console-js.mjs` / `check-console-fns.mjs` / `check-console-pages.mjs`（面板三项）

**不能只跑单元测试**：面板是纯前端，单元测试覆盖不到。
面板改动至少要过上面三个检查，能打开页面自己点一遍更好。

---

## 3. 出错要能查

- 新功能的关键失败点必须有日志，日志要能指出「哪个功能、什么原因」
- 不要写「失败」两个字就完事（参照 `docs/BUGS.md` 里「无返回」那一条的教训）

---

## 4. 框架与适配器保持分离

- 主仓（`YF-Robot`）**不出现**任何微信/平台自动化代码
- 需要平台能力时，走 `adapters/<名字>/` 或独立仓库
- 提 PR / 提交前自查一遍：主仓里有没有 Windows 窗口、剪贴板、UIA 相关代码
