## 修 bug 的固定动作

1. **先复现**：能拿日志/接口/真实文件复现就别猜。上面每一条的根因都来自读数。
2. **定位到最底层**：现象 → 直接原因 → 根因（哪个判断、哪行代码、哪个环境假设）。
3. **一处修复**：同类判断只保留一份实现（配置读写、质量判定、主人判定都要收）。
4. **补回归测试**：要能在修复前失败、修复后通过。
5. **写进这里**：一行一个问题，别让下一个人重踩。
