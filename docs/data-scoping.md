# 数据隔离：一张角色卡一套数据

## 为什么要隔离

以前三个库（知识库 / 逻辑库 / 词库）和记忆都是**全局一份**，换角色卡只换了
system 提示词。结果：

- 客服卡继承了海王卡的经验「被骂先别软」→ 一上来就开喷
- 换成古风角色，词库还是「绝绝子、破防了」
- 和同一个人聊过的事，换卡后新角色一清二楚

现在按卡隔离，换卡 = 换整套上下文。

---

## 目录结构

```
data/
  dafeiyu/                   ← 一个角色卡一个作用域
    kb/                      知识库文档（每篇一个 json）
    logic.json               逻辑库（经验）
    memory/                  记忆（每个会话一个文件）
    words/                   词库（可选，有就覆盖公共的）
  jingjing-wg/               另一张卡，互不可见
    …
resources/                  公共词库（没有自己词库的卡都用这份）
```

作用域目录名 = 角色卡 id（非法字符替换成 `_`）。

---

## 哪些跟卡走，哪些不跟

| 数据 | 跟卡走 | 说明 |
|---|---|---|
| 知识库 | ✅ | 每张卡可以有完全不同的资料 |
| 逻辑库 | ✅ | 每张卡的经验互不影响 |
| 记忆 | ✅ | 同一联系人，不同卡记得的东西也不同 |
| 词库 | ✅ 可覆盖 | 卡内有 `words/*.txt` 就用自己的，没有就退回 `resources/` |
| 素材库（表情包） | ❌ | 图是共用的，换角色照样能发 |
| 配置（模型/Key/开关） | ❌ | 全局一份 |
| 日志 | ❌ | 全局一份 |

---

## 换卡时发生了什么

1. 写 `config.json` 的 `card` 字段
2. 热加载人设（不用重启）
3. 重建按卡隔离的存储（知识库 / 逻辑库 / 记忆指向新卡目录）

```js
// core/admin.mjs
this.engine.persona = who;
this.engine.reloadScopedStores();   // ← 关键
```

实测：

```
dafeiyu      → 逻辑库 4 条
切到 jingjing-wg → 逻辑库 0 条（新卡是干净的）
切回 dafeiyu → 逻辑库 4 条
```

## 老数据怎么办

升级后第一次启动会自动搬迁：把原来的 `data/kb`、`data/logic.json`、
`data/memory` 搬到**当前角色卡**的作用域下，只搬一次。

规则：

- 目标已有数据 → 跳过，不覆盖（老数据留着让你自己处理）
- 跨盘改名失败 → 自动退回复制

启动日志会打印：

```
[scope] 已把老数据搬进当前角色卡：kb、logic、memory
```

## 副作用（要知道）

**① 换卡会「失忆」**

新卡看不到旧卡的记忆，这是设计意图。但如果你只是想换个人设说话、
记忆还想保留，就得手动复制目录：

```bash
cp -r data/dafeiyu/memory data/newcard/memory
```

**② 公共词库是共享的**

`resources/` 下的词库所有卡共用。如果某张卡想要完全不同的风格，
在 `data/<card>/words/` 放一份就行。

**③ 素材库不分卡**

换角色后她还能发同一批表情包。如果你想让不同角色用不同表情包，
现在的结构做不到，需要额外加一层（暂时没做）。
